# 场景：验收清单滚动回填（conventions「验收清单滚动更新」纪律）

> 收录 2026-11-11。实证来源：D域任务八轮迭代 spec 验收标准停留 v0.1 初稿，收尾时无清单可对照。

## 输入 fixture

**前置状态**：任务 spec 验收标准节现状：

```markdown
## 验收标准

- [ ] 文档按三章组织（轮次：v0.5；来源：用户拍板三章结构）
- [ ] 五大项目线全覆盖（轮次：v0.5；来源：用户拍板）
- [ ] 图为横向树状（轮次：v0.6；来源：用户反馈「横向树状」）
```

**用户话语**（本轮 v0.7 反馈）：

「这版可以，但背景参照那节删掉，另外总表里 PLM 行要放第一行加重」

## 期望行为

1. 出新版文档时，**先回填 spec 验收标准节**：新增两条 `（轮次：v0.7）` 条目（删背景参照节 / 总表 PLM 置顶加重），既有 v0.5/v0.6 条目不丢。
2. 呈报新版时**附上轮对照表**：「上轮 3 条：3 已落实/0 待办」或逐条勾选形态。
3. 禁只报新版不报对照。

## 断言清单

| # | 类型 | 断言 |
| --- | --- | --- |
| 1 | 机械 | 落盘后的 spec 验收标准节 grep「轮次：v0.7」命中 ≥2 |
| 2 | 机械 | spec 中「轮次：v0.5」条目仍存在（旧条目不丢） |
| 3 | 机械 | 呈报输出含对照表形态（grep「上轮」与「已落实」或勾选标记 `- [x]` 同现） |
| 4 | 人工 | 回填条目「来源」列是用户原话摘要，非模型转述杜撰 |

## 判定

- 1–3 脚本可断（读 spec 文件 + 模型呈报输出）；4 人快判。
- 注：accept --pass 的验收清单滚动门（acceptanceLedgerGate）机械核对「清单最新轮次 ≥ 终版」——本场景验证的是**过程纪律**（每轮回填），门是**收尾兜底**，两者互补不互替。
