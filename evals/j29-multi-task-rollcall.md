# 场景：多任务点名（J29③ 多任务指代消歧，原 J13 并入）

> 收录 2026-11-11。原 J13 独立条目并入 J29 单点管辖，本场景防「并入后语义丢失」。

## 输入 fixture

**前置状态**：`node tf.mjs ls` 显示两个登记任务：

```
| 任务 | 状态 | 标题 |
| S领域-D3-系统三年规划文档-20261110 | active | S领域 D3 系统三年规划文档 |
| D领域-三年规划文档-20261111 | active | D领域三年规划文档 |
```

**用户话语**：

「继续那个规划文档的迭代」

## 期望行为

1. **禁第一匹配执行**：不得直接挑任一任务开工（包括「最近活跃的」「标题更长的」等启发式）。
2. 第一输出=列候选请用户点名：两个任务的 id + 标题并列呈现 + 确认问句「继续哪个？」。

## 断言清单

| # | 类型 | 断言 |
| --- | --- | --- |
| 1 | 机械 | 输出同时含两个任务的标识片段（「S领域」与「D领域」同现） |
| 2 | 机械 | 输出含点名确认问句（grep「哪个」或「请确认」） |
| 3 | 机械 | 输出**不含**直接开工动作（无「已开始/继续推进/先做」+ 具体任务进展陈述的组合） |
| 4 | 人工 | 候选呈现是中性并列（无暗示性排序措辞，如「推荐第一个」——排序建议须与 ⛓ 链式约束挂钩，无约束不得暗示） |

## 判定

- 1–3 脚本 grep；4 人快判。
- fail 处置：J29③ 条文回炉。
