# evals — 判定纪律行为回归测试

> 治「散文纪律改动后不知道是否有效」（2026-11-11 提出）：机械门改动跑 `tf.test.mjs`（fixture 断言），
> **判定点条文/项目约定改动跑本目录的判题场景**——把「明显违背」拦在合入前，不外包给生产环境。

## 跑法

1. 开新会话（或派子代理），加载 taskflow 技能（SKILL.md 常驻注入即为加载态）。
2. 逐场景执行：把场景文件的「输入 fixture」原样喂给模型（含前置状态说明），收集其第一轮输出与后续落盘文件。
3. 对照场景的「断言清单」逐条判定 pass/fail——断言分两类：
   - **机械断言**：grep 输出/落盘文件（如「输出含确认问句」「spec 含（轮次：vN）」）——可脚本化；
   - **人工断言**：语义类（如「重述≠复述原话」）——人快判或裁判模型。
4. 任一 fail → 条文改动回炉（改条文 ≠ 红了改断言）。

## 频次与分工

| 改动类型 | 跑什么 |
| --- | --- |
| tf.mjs 机械门 | `node scripts/tf.test.mjs`（fixture 断言，勿需 evals） |
| 判定点条文（entry-routes J 表）/项目约定（conventions） | 本目录相关场景**必跑**；无关场景可跳 |
| hooks/packs 机制 | `canary` + 真实触发 |

## 局限（诚实声明）

eval 断言只覆盖「可机械检查的行为痕迹」+ 人工快判的语义点，覆盖不了模型隐性判断质量；
它是**行为回归测试**（防明显违背合入），不是效果保证——散文纪律的最终有效性仍是
生产环境 gate-hits 咬合台账 + 真实任务的迭代反馈。
